ChatController (/api/v1/chat/*)
------------------------------------------------------------------------------

1. GET /api/v1/chat/sessions - List user's chat sessions
   
   Query Parameters:
     - userId (required): Long - The user ID
     - activeOnly (optional): boolean - Filter active sessions only (default: false)
   
   Example Request:
     GET /api/v1/chat/sessions?userId=1&activeOnly=false
   
   Example Response (200 OK):
     [
       {
         "id": 1,
         "userId": 1,
         "title": "Product inquiry",
         "isActive": true,
         "createdAt": "2025-12-01T10:00:00",
         "lastMessageAt": "2025-12-01T10:30:00"
       }
     ]

2. POST /api/v1/chat/sessions - Create new chat session
   
   Request Body:
     {
       "userId": 1,
       "title": "Help with bulk order"
     }
   
   Example Response (201 CREATED):
     {
       "id": 2,
       "userId": 1,
       "title": "Help with bulk order",
       "isActive": true,
       "createdAt": "2025-12-04T12:00:00",
       "lastMessageAt": null
     }

3. GET /api/v1/chat/sessions/{sessionId}/messages - Get messages in session
   
   Path Parameters:
     - sessionId: Long - The session ID
   
   Query Parameters:
     - userId (required): Long - The user ID (for authorization)
     - limit (optional): Integer - Max number of messages to return
   
   Example Request:
     GET /api/v1/chat/sessions/1/messages?userId=1&limit=50
   
   Example Response (200 OK):
     [
       {
         "id": 1,
         "sessionId": 1,
         "role": "USER",
         "content": "What laptops do you have?",
         "createdAt": "2025-12-01T10:00:00"
       },
       {
         "id": 2,
         "sessionId": 1,
         "role": "ASSISTANT",
         "content": "We have several laptop options...",
         "createdAt": "2025-12-01T10:00:05"
       }
     ]

4. POST /api/v1/chat/sessions/{sessionId}/messages - Ask question (AI-powered)
   
   Path Parameters:
     - sessionId: Long - The session ID
   
   Request Body:
     {
       "userId": 1,
       "question": "What is the minimum order quantity for laptop SKU-001?"
     }
   
   Example Response (200 OK):
     {
       "sessionId": 1,
       "question": "What is the minimum order quantity for laptop SKU-001?",
       "answer": "The minimum order quantity for laptop SKU-001 is 10 units...",
       "sources": [
         {
           "type": "product",
           "id": "101",
           "name": "Business Laptop Pro"
         }
       ]
     }

AnalyticsController (/api/v1/analytics/*)
------------------------------------------------------------------------------

1. POST /api/v1/analytics/track - Track user interaction
   
   Request Body:
     {
       "userId": 1,
       "productId": 101,
       "variantId": 201,                        // optional
       "interactionType": "VIEW",               // VIEW, ADD_TO_CART, ORDER
       "sessionId": "session-abc-123",          // optional, for session tracking
       "metadata": {                            // optional, additional context
         "source": "search_results",
         "position": 3
       }
     }
   
   Example Response (202 ACCEPTED):
     {
       "interactionId": 12345,
       "interactionType": "VIEW",
       "tracked": true
     }
   
   Interaction Types:
     - VIEW: User viewed a product detail page
     - ADD_TO_CART: User added product to cart
     - ORDER: User completed order with this product

Phase 7: MCP (Model Context Protocol) ❌ NOT NEEDED
================================================================================

❌ MCP Server/Client implementation - SKIPPED

Reason: Agentic RAG provides equivalent functionality:
- LLM Router replaces MCP tool selection
- Direct API calls replace MCP tool invocations
- Simpler architecture, fewer dependencies
- Same capabilities without MCP overhead

The Agentic RAG pattern in chat_service.py achieves:
- search_knowledge_base → Vector search in knowledge_base collection
- search_products → Vector search + Spring Boot API enrichment
- get_product_details → Direct call to /internal/ai/products/{id}
- get_supplier_info → Direct call to /internal/ai/suppliers/{id}
- get_inventory_status → Direct call to /internal/ai/inventory/{id}
