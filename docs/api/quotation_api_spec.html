📋 Quotation Management API Specification

Design Principle: This API uses a simplified single-entity quotation system with line-item level status tracking. Each quotation represents communication between one retailer and one supplier. When a retailer's cart contains items from multiple suppliers, the system automatically creates multiple quotations.

1. Quotation Management

POST /api/v1/quotations
Description
Create a new quotation request from retailer to supplier. The system automatically determines the supplier based on the product variants in the request (since variant-product-supplier has 1-1-1 relationship). If items belong to different suppliers, the system will create multiple quotations.
Request Body
{
  "items": [                          *required, min 1
    {
      "variantId": long,              *required
      "requestedQuantity": integer,   *required, min: 1
      "targetPrice": number,          optional, positive
      "deliveryDate": "2024-02-15",   optional
      "notes": "string"               optional
    }
  ],
  "notes": "string"                   optional - general notes for entire quotation
}
Response Body (201 Created)
{
  "quotations": [
    {
      "quotationId": long,
      "quotationNumber": "string",
      "supplierId": long,
      "supplierName": "string",
      "itemCount": integer,
      "status": "PENDING_SUPPLIER"
    }
  ],
  "message": "Created 2 quotation(s) for 2 supplier(s)"
}
Behavior
  1. Validate items not empty → 400 BAD REQUEST
  2. For each item:
    • Validate variantId exists → 404 NOT FOUND
    • Fetch product and supplier info from variant
    • Validate requestedQuantity > 0 → 400 BAD REQUEST
    • If targetPrice provided, validate > 0 → 400 BAD REQUEST
    • If deliveryDate provided, validate future date → 400 BAD REQUEST
  3. Group items by supplierId (since variant → product → supplier is 1-1-1)
  4. For each supplier group:
    • Generate unique quotation number
    • Create Quotation record with status = "PENDING_SUPPLIER"
    • Create QuotationItem records for each item in the group
    • Set validUntil to 30 days from now
  5. Return 201 CREATED with list of created quotations
GET /api/v1/quotations
Description
List quotations with pagination and filtering
Query Parameters
role string *required - "retailer" or "supplier"
status string Filter by status (PENDING_SUPPLIER, PENDING_RETAILER, FINALIZED, CANCELLED, EXPIRED)
supplierId long Filter by supplier ID
retailerId long Filter by retailer ID
page, size, sort Standard pagination parameters (default: page=0, size=20)
Response Body (200 OK)
{
  "content": [
    {
      "quotationId": long,
      "quotationNumber": "string",
      "retailerId": long,
      "retailerName": "string",
      "supplierId": long,
      "supplierName": "string",
      "itemCount": integer,
      "totalEstimatedAmount": number,
      "status": "PENDING_SUPPLIER" | "PENDING_RETAILER" | "FINALIZED" | "CANCELLED" | "EXPIRED",
      "validUntil": "2024-01-31T23:59:59",
      "createdAt": "2024-01-01T10:00:00",
      "respondedAt": "2024-01-02T14:30:00"
    }
  ],
  "page": {
    "size": 20,
    "number": 0,
    "totalElements": 50,
    "totalPages": 3
  }
}
Behavior
  1. Validate role parameter → 400 BAD REQUEST if missing or invalid
  2. Apply role-based filtering (retailer sees their sent quotations, supplier sees received)
  3. Build query with all provided filters
  4. Apply pagination and sorting
  5. Return 200 OK with paginated results
GET /api/v1/quotations/{quotationId}
Description
Get detailed quotation information including all line items with request and response data
Response Body (200 OK)
{
  "quotationId": long,
  "quotationNumber": "string",
  "retailerId": long,
  "retailerName": "string",
  "supplierId": long,
  "supplierName": "string",
  "status": "PENDING_SUPPLIER" | "PENDING_RETAILER" | "FINALIZED" | "CANCELLED" | "EXPIRED",
  "items": [
    {
      "quotationItemId": long,
      "variantId": long,
      "productId": long,
      "productName": "string",
      "variantName": "string",
      "imageUrl": "string",
      
      // Retailer's request
      "requestedQuantity": integer,
      "targetPrice": number,
      "requestedDeliveryDate": "2024-02-15",
      "retailerNotes": "string",
      
      // Supplier's response (null if not yet responded)
      "itemStatus": "PENDING" | "ACCEPTED" | "PARTIAL" | "REJECTED",
      "offeredQuantity": integer,
      "offeredPrice": number,
      "offeredDeliveryDate": "2024-02-20",
      "leadTimeDays": integer,
      "supplierNotes": "string",
      "rejectionReason": "string",
      
      // Retailer's final decision (null if not yet finalized)
      "retailerAction": "ACCEPT" | "REJECT" | "ACKNOWLEDGE"
    }
  ],
  "retailerNotes": "string",
  "supplierNotes": "string",
  "termsAndConditions": "string",
  "validUntil": "2024-01-31T23:59:59",
  "orderId": long,                    // if converted to order
  "createdAt": "2024-01-01T10:00:00",
  "respondedAt": "2024-01-02T14:30:00",
  "finalizedAt": "2024-01-03T09:15:00"
}
Behavior
  1. Query Quotation by ID
  2. If not found → 404 NOT FOUND
  3. Fetch associated QuotationItems with product and variant details
  4. Return 200 OK
PATCH /api/v1/quotations/{quotationId}/respond
Description
Supplier responds to quotation request with offer details for each line item
Request Body
{
  "items": [                          *required, must match all quotation items
    {
      "quotationItemId": long,        *required
      "itemStatus": "ACCEPTED" | "PARTIAL" | "REJECTED",  *required
      "offeredQuantity": integer,     *required if status is ACCEPTED or PARTIAL
      "offeredPrice": number,         *required if status is ACCEPTED or PARTIAL
      "offeredDeliveryDate": "2024-02-20",  optional
      "leadTimeDays": integer,        optional
      "supplierNotes": "string",      optional
      "rejectionReason": "string"     *required if status is REJECTED
    }
  ],
  "validUntil": "2024-02-15T23:59:59", optional, default 30 days from now
  "supplierNotes": "string",          optional - general notes for entire quotation
  "termsAndConditions": "string"      optional
}
Response Body (200 OK)
{
  "quotationId": long,
  "status": "PENDING_RETAILER",
  "respondedAt": "2024-01-02T14:30:00",
  "message": "Quotation response submitted successfully. Awaiting retailer review."
}
Behavior
  1. Query Quotation by ID → 404 NOT FOUND
  2. Validate current status is PENDING_SUPPLIER → 400 BAD REQUEST if not
  3. Verify supplier owns this quotation → 403 FORBIDDEN
  4. Check quotation not expired → 400 BAD REQUEST
  5. Validate all quotation items are included in response → 400 BAD REQUEST
  6. For each item in response:
    • Validate quotationItemId exists in this quotation → 400 BAD REQUEST
    • If itemStatus is ACCEPTED or PARTIAL:
      • Validate offeredQuantity > 0 → 400 BAD REQUEST
      • Validate offeredPrice > 0 → 400 BAD REQUEST
      • If offeredDeliveryDate provided, validate future date → 400 BAD REQUEST
    • If itemStatus is REJECTED, validate rejectionReason provided → 400 BAD REQUEST
  7. Update all QuotationItem records with supplier response data
  8. Update Quotation status to PENDING_RETAILER
  9. Set respondedAt timestamp
  10. Return 200 OK
PATCH /api/v1/quotations/{quotationId}/finalize
Description
Retailer reviews supplier's response and finalizes the quotation, optionally creating a purchase order
Request Body
{
  "items": [                          *required, must include all non-rejected items
    {
      "quotationItemId": long,        *required
      "retailerAction": "ACCEPT" | "REJECT" | "ACKNOWLEDGE"  *required
    }
  ],
  "createOrder": boolean,             optional, default false
  "notes": "string"                   optional
}
Response Body (200 OK)
{
  "quotationId": long,
  "status": "FINALIZED",
  "orderId": long,                    // only if createOrder was true and at least one item accepted
  "acceptedItemCount": integer,
  "rejectedItemCount": integer,
  "finalizedAt": "2024-01-03T09:15:00",
  "message": "Quotation finalized successfully. Purchase order #PO-2024-001 created."
}
Behavior
  1. Query Quotation by ID → 404 NOT FOUND
  2. Validate current status is PENDING_RETAILER → 400 BAD REQUEST if not
  3. Verify retailer owns this quotation → 403 FORBIDDEN
  4. Check quotation not expired → 400 BAD REQUEST
  5. Validate all non-rejected items have retailer action → 400 BAD REQUEST
  6. For each item in request:
    • Validate quotationItemId exists → 400 BAD REQUEST
    • Update retailerAction field
  7. Update Quotation status to FINALIZED
  8. Set finalizedAt timestamp
  9. If createOrder is true and at least one item has retailerAction = ACCEPT:
    • Create PurchaseOrder with accepted items
    • Link orderId to Quotation
  10. Return 200 OK with summary
PATCH /api/v1/quotations/{quotationId}/cancel
Description
Cancel a quotation (allowed by either retailer or supplier before finalization)
Request Body
{
  "reason": "string"                  optional
}
Response Body (200 OK)
{
  "quotationId": long,
  "status": "CANCELLED",
  "cancelledAt": "2024-01-02T16:00:00",
  "message": "Quotation cancelled successfully"
}
Behavior
  1. Query Quotation by ID → 404 NOT FOUND
  2. Validate status is not FINALIZED or CANCELLED → 400 BAD REQUEST
  3. Verify user is either the retailer or supplier of this quotation → 403 FORBIDDEN
  4. Update status to CANCELLED
  5. Record cancellation reason if provided
  6. Return 200 OK

2. Quotation Statistics

GET /api/v1/quotations/stats
Description
Get quotation statistics for dashboard display
Query Parameters
role string *required - "retailer" or "supplier"
dateFrom date Start date for statistics (default: 30 days ago)
dateTo date End date for statistics (default: today)
Response Body (200 OK)
{
  "period": {
    "from": "2024-01-01",
    "to": "2024-01-31"
  },
  "summary": {
    "totalQuotations": integer,
    "pendingSupplier": integer,
    "pendingRetailer": integer,
    "finalized": integer,
    "cancelled": integer,
    "expired": integer
  },
  "acceptanceRate": number,           // percentage of finalized quotations with accepted items
  "averageResponseTime": number,      // in hours
  "totalEstimatedValue": number
}
Behavior
  1. Validate role parameter → 400 BAD REQUEST
  2. Apply date range filters (default to last 30 days)
  3. Calculate statistics based on role perspective
  4. Return 200 OK

3. Data Models

Quotation Status Flow
PENDING_SUPPLIER  → Waiting for supplier to respond
       ↓
PENDING_RETAILER → Supplier responded, waiting for retailer to finalize
       ↓
FINALIZED        → Retailer reviewed and finalized (may include order creation)

CANCELLED        → Either party cancelled before finalization
EXPIRED          → Exceeded validUntil date without finalization
Quotation Item Status Values
PENDING   → Supplier has not yet responded to this item
ACCEPTED  → Supplier accepts the full requested quantity at offered price
PARTIAL   → Supplier can fulfill only partial quantity or different terms
REJECTED  → Supplier cannot fulfill this item
Retailer Action Values
ACCEPT      → Retailer accepts the supplier's offer for this item
REJECT      → Retailer declines the supplier's offer
ACKNOWLEDGE → Retailer acknowledges a rejected item (no action needed)
Note on Batch Operations: When creating quotations from a cart with items from multiple suppliers, the system automatically groups items by supplier and creates separate quotations. Each quotation maintains its own independent lifecycle and communication channel between the specific retailer-supplier pair.
